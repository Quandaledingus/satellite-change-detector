# Satellite Change Detector

A tool for comparing two images of the same place taken at different times and
highlighting where they differ. The long-term goal is detecting land-cover change
(vegetation loss, urban growth, flooding) in Sentinel-2 satellite imagery.

**Current status: Phase 1.** Plain RGB image differencing with an adjustable threshold,
a Streamlit interface, and unit tests. Georeferenced rasters and NDVI are next.

## What it does right now

- Loads two PNG/JPEG images and checks that they are readable and the same size
- Computes the per-pixel absolute difference, averaged over the R, G and B channels
- Flags pixels whose difference is above a user-chosen threshold
- Shows a difference heatmap, a change-mask overlay, and the percentage of flagged pixels

## Setup

Requires Python 3.14.

```bash
git clone https://github.com/Quandaledingus/satellite-change-detector.git
cd satellite-change-detector
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## Running

```bash
python scripts/make_sample_data.py   # (re)creates data/sample/ - already included in the repo
streamlit run app.py
```

Then open http://localhost:8501 in a browser.

## How it works

For each pixel, with RGB values scaled to 0–1:

```
difference = (|R_after - R_before| + |G_after - G_before| + |B_after - B_before|) / 3
changed    = difference > threshold
```

Images are converted to floating point *before* subtracting. With 8-bit integers,
`10 - 20` wraps around to `246`, which would silently produce wrong results; the code
raises an error if it's given integer arrays.

### Limitations

Differencing detects *any* change in pixel color, so a flagged pixel is not proof that
something changed on the ground. Things that cause false positives:

- lighting, haze and atmospheric differences between dates
- seasonal changes in vegetation
- clouds and cloud shadows
- spatial misalignment (shifted images make every edge look like a change)
- different sensors or processing pipelines

It also can't report area in m², because PNG/JPEG files don't store how big a pixel is
on the ground. That needs georeferenced data (Phase 2).

## Sample data

`data/sample/` contains a **synthetic** image pair generated by
`scripts/make_sample_data.py` (seed 42). It is not real satellite imagery. It's a
made-up landscape with two planted changes (a cleared forest patch and a new building)
plus an 8% brightness increase and random noise in the "after" image. Because the
changes are planted, `truth_mask.png` records exactly which pixels really changed.

See [data/README.md](data/README.md) for how to get real Sentinel-2 imagery.

## Results so far

Single run on the synthetic sample pair (256×256 px, 5,009 truly changed pixels):

| Threshold | Flagged | True positives | False positives | False negatives |
|-----------|---------|----------------|-----------------|-----------------|
| 0.02      | 73.12%  | 5,009          | 42,910          | 0               |
| 0.05      | 25.69%  | 5,009          | 11,827          | 0               |
| 0.10      | 9.73%   | 5,009          | 1,369           | 0               |
| 0.15      | 7.63%   | 4,952          | 48              | 57              |
| 0.20      | 5.86%   | 3,839          | 0               | 1,170           |
| 0.30      | 2.78%   | 1,824          | 0               | 3,185           |

Low thresholds get flagged everywhere because of the brightness shift; high thresholds
miss real changes. This is one easy synthetic example, **not** an evaluation of how well
the method works on real imagery. Proper evaluation is planned for Phase 5.
